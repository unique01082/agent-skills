# LightMesh tool catalog

Generated by `scripts/gen_tools_reference.mjs` — do not edit by hand. Every graph-scoped tool also
accepts optional `graphId` (omit inside WebMCP to use the open graph; pass it over remote MCP).
Required arguments are marked **bold**.

## `session_context` — read

Open graph and the selected node/edge (resolved to full records). Selection only exists over WebMCP; over remote MCP it is null.

No arguments.

## `graph_list` — read

Every graph you own, newest first: id, name, description, last change.

No arguments.

## `node_set_avatar` — write

Store a picture for a node (base64, PNG/JPEG/WebP/GIF, ≤2 MB, no SVG) and point metadata.avatar at it.

- **nodeId** (`string`)
- **imageBase64** (`string`)
- **mimeType** (`string`)

## `file_upload` — write

Store a file (base64, ≤10 MB, no HTML/SVG/scripts); returns { provider, bucket, key, mimeType, size } to use as a data_add source { type: "object", … }.

- **fileBase64** (`string`)
- **mimeType** (`string`)

## `node_generate_avatar` — write

Only when the deployment has an image model. Generates a square avatar from a picture description (≤500 chars) and sets it.

- **nodeId** (`string`)
- **prompt** (`string`)

## `graph_get` — read

The whole graph as a LightMesh file: schema block, graph identity, every node and every edge. Start here when you need an overview; prefer graph_subgraph or graph_filter on a large graph.

No arguments.

## `graph_set_info` — write

Renames, re-describes, restyles, or sets the portable presentation journey. Only the fields you pass change.

- id (`string`) — New graph id. Changing it makes a new graph rather than renaming this one.
- name (`string`) — New graph name.
- description (`string`) — New graph description.
- typeStyles (`object`) — Node type → how to draw it. Replaces the whole map when passed — omit to leave the graph's current styles alone. Keys are node types; a type not listed falls back to its default icon and colour.
- journey (`object`) — A presentation route through the graph. Each step highlights nodeIds together; use [] for an overview step.

## `journey_get` — read

Read the graph presentation journey, including its ordered steps. Returns null when none exists.

No arguments.

## `journey_set` — write

Replace the presentation journey atomically. Invalid node references or step ids change nothing.

- **journey** (`object`) — A presentation route through the graph. Each step highlights nodeIds together; use [] for an overview step.

## `journey_step_upsert` — write

Insert or replace a presentation step by stable id. Optional index moves it to a zero-based position; omitted appends.

- **step** (`object`) — 
- index (`integer`) — Zero-based position after removing an existing step with the same id.

## `journey_step_remove` — write

Remove one presentation step by stable id without changing graph nodes or other steps.

- **id** (`string`) — Stable id of the step to remove.

## `graph_import` — write

Applies a whole LightMesh file at once. mode "merge" adds and overwrites by id and deletes nothing — this is how you apply a generated patch. mode "replace" swaps the entire graph for the file. The file is validated structurally and referentially first; an invalid file changes nothing.

- **file** (`object`) — A complete LightMesh file: { schema, graph, nodes, edges }.
- mode (`"merge" \| "replace"`) — How to apply it. Defaults to "merge".

## `graph_search` — read

Case-insensitive substring search over node name, type, property values and attached text/links. Returns matching nodes.

- **term** (`string`) — What to search for.

## `graph_filter` — read

Locates nodes without reading the whole graph: by type, property, metadata, context, the source file they document, or whether they carry an attachment at all. A property or metadata filter is written "key" (the key exists) or "key=value" (its value contains value); both halves match on case-insensitive substring. Every argument is optional and they combine with AND. Returned edges are limited to those whose endpoints both survive the node filter. Use graph_search instead when you have a phrase rather than a field.

- nodeTypes (`string[]`) — Keep only nodes of these types.
- edgeTypes (`string[]`) — Keep only edges of these types.
- nodeProperty (`string`) — Node property filter, "key" or "key=value".
- edgeProperty (`string`) — Edge property filter, "key" or "key=value".
- metadata (`string`) — Node metadata filter, "key" or "key=value".
- contexts (`string[]`) — Keep only nodes/edges tagged with one of these metadata.contexts values.
- sourcePath (`string`) — Keep only nodes with an attachment whose URI contains this — a file path, or any part of a deeplink. Finds the node that documents a given file.
- hasAttachment (`boolean`) — true: only nodes carrying an attachment. false: only nodes carrying none, which is how you find what still needs documenting.
- attachmentKind (`string`) — Narrows hasAttachment to one kind, e.g. "source" or "insight".

## `graph_contexts` — read

Every distinct metadata.contexts value used anywhere in the graph — the vocabulary graph_filter accepts for its contexts argument.

No arguments.

## `graph_neighbors` — read

Nodes one hop from this node, following edges in either direction.

- **nodeId** (`string`) — Node to start from.

## `graph_path` — read

Shortest path between two nodes, treating edges as undirected. Returns the nodes along the path, or not_found when the two are in disconnected parts of the graph.

- **fromNodeId** (`string`) — Node to start from.
- **toNodeId** (`string`) — Node to reach.

## `graph_subgraph` — read

Everything within depth hops of a node, plus the edges among those nodes. The cheap way to read one region of a large graph. Pass direction "out" to read the node's branch — only what it points at — which is what you want before and after expanding one; "both" sweeps in whatever its parents also touch, which on a connected graph is most of it.

- **nodeId** (`string`) — Node at the centre.
- depth (`integer`) — How many hops out. Defaults to 1.
- direction (`"out" \| "in" \| "both"`) — Which way to walk: "out" for the branch below this node, "in" for what leads to it, "both" to ignore direction. Defaults to "both".

## `node_get` — read

One node by id, with its properties, metadata and attached data.

- **nodeId** (`string`) — Node id.

## `node_create` — write

Adds a node. type and name are required; id is generated when you omit it. Fails with conflict if the id you supply is taken.

- id (`string`) — Optional stable id. Generated when omitted.
- **type** (`string`) — Node type, e.g. "service", "component", "concept". An open vocabulary, not a fixed enum.
- **name** (`string`) — Human-readable node name.
- properties (`object`) — Domain facts about the node. Merge-patched key by key; an explicit null removes a key.
- metadata (`object`) — Bookkeeping. Two keys the app reads: "contexts": string[] for grouping, and "avatar", an object-storage reference { provider, bucket, key, mimeType } for the picture drawn instead of the node's type icon — set one with node_set_avatar, remove it with "avatar": null. Merge-patched key by key; an explicit null removes a key.

## `node_update` — write

Changes the fields you pass and leaves the rest alone. Attached data is never touched here — use the data_* and insight_* tools for that.

- **nodeId** (`string`) — Node to update.
- type (`string`) — Node type, e.g. "service", "component", "concept". An open vocabulary, not a fixed enum.
- name (`string`) — Human-readable node name.
- properties (`object`) — Domain facts about the node. Merge-patched key by key; an explicit null removes a key.
- metadata (`object`) — Bookkeeping. Two keys the app reads: "contexts": string[] for grouping, and "avatar", an object-storage reference { provider, bucket, key, mimeType } for the picture drawn instead of the node's type icon — set one with node_set_avatar, remove it with "avatar": null. Merge-patched key by key; an explicit null removes a key.

## `node_delete` — write

Removes the node and cascade-deletes every edge attached to it. Returns the ids of the edges that went with it. Not undoable.

- **nodeId** (`string`) — Node to delete.

## `node_edges` — read

Edges pointing out of, or in to, a node — with direction, unlike graph_neighbors.

- **nodeId** (`string`) — Node id.
- direction (`"outgoing" \| "incoming"`) — Which way the edges run. Defaults to "outgoing".

## `edge_get` — read

One edge by id, with its properties, metadata and attached data.

- **edgeId** (`string`) — Edge id.

## `edge_create` — write

Connects two existing nodes. Both endpoints must already be in the graph — create the nodes first, or use graph_import to add nodes and edges in one call.

- id (`string`) — Optional stable id. Generated when omitted.
- **source** (`string`) — Id of the node the edge runs from.
- **target** (`string`) — Id of the node the edge runs to.
- **type** (`string`) — Edge type, e.g. "depends-on", "emits", "related-to". An open vocabulary.
- label (`string`) — Display label. Defaults to the edge type.
- properties (`object`) — Domain facts about the edge. Merge-patched key by key; an explicit null removes a key.
- metadata (`object`) — Bookkeeping, including "contexts": string[]. Merge-patched key by key; an explicit null removes a key.

## `edge_update` — write

Changes the fields you pass. Re-pointing source or target requires the new node to exist. Attached data is never touched here.

- **edgeId** (`string`) — Edge to update.
- source (`string`) — Re-point the edge to run from this node instead.
- target (`string`) — Re-point the edge to run to this node instead.
- type (`string`) — Edge type, e.g. "depends-on", "emits", "related-to". An open vocabulary.
- label (`string`) — Display label. Defaults to the edge type.
- properties (`object`) — Domain facts about the edge. Merge-patched key by key; an explicit null removes a key.
- metadata (`object`) — Bookkeeping, including "contexts": string[]. Merge-patched key by key; an explicit null removes a key.

## `edge_delete` — write

Removes one edge. The nodes it connected stay.

- **edgeId** (`string`) — Edge to delete.

## `insight_add` — write

Attaches an AI-authored note to a node or edge. Use this to record a finding — what a service actually does, why two components are coupled — where the next reader will see it.

- **on** (`"node" \| "edge"`) — Whether the attachment hangs off a node or an edge.
- **targetId** (`string`) — Id of that node or edge.
- title (`string`) — Short label for the insight.
- **body** (`string`) — The insight itself, as plain text or Markdown.
- insightId (`string`) — Optional stable id, unique within this node/edge. Generated when omitted.

## `insight_update` — write

Rewrites an insight already attached to a node or edge. Pass the id insight_add returned.

- **on** (`"node" \| "edge"`) — Whether the attachment hangs off a node or an edge.
- **targetId** (`string`) — Id of that node or edge.
- **insightId** (`string`) — Id of the insight to rewrite.
- title (`string`) — New label. Left alone when omitted.
- body (`string`) — New text. Left alone when omitted.

## `graph_apply_patch` — write

Applies a list of node and edge changes as one transaction, and returns a diff of what it did. If any change fails, every change in the batch is rolled back and nothing is written — so a patch is always all or nothing. Order matters: give a createNode an "id" and a later createEdge in the same patch can name it as its source or target. This is the tool to use when extending a branch; it costs one call instead of one per node, and it cannot leave the graph half-edited.

- **changes** (`object[]`) — The changes, applied in order.
- validate (`boolean`) — Include a graph_validate report of what the write left behind, in the same response. Worth passing after a batch; off by default because it scans the whole graph.

## `graph_upsert_subgraph` — write

Brings one branch of the graph into the state you describe, leaving the rest untouched: each node and edge you pass is created if its id is new and updated if it already exists. Safer than graph_import for editing a region that already exists, because it can only touch what you name. Nodes already in the branch that you do not mention are reported as "stale"; pass prune to delete them instead. Transactional, like graph_apply_patch.

- **rootNodeId** (`string`) — The branch root. Must already exist; it anchors what counts as "the branch".
- nodes (`object[]`) — Nodes to create or update. An entry with a known id updates; without one, creates.
- edges (`object[]`) — Edges to create or update. Wire new nodes to the root here, or they will be orphans.
- depth (`integer`) — How far below the root the branch reaches, for deciding what is stale. Defaults to 2.
- prune (`boolean`) — Delete branch nodes you did not mention, instead of only reporting them. Cascades to their edges. Defaults to false.
- attachWith (`string`) — Edge type used to wire every node this call creates to the root, so expanding a node does not mean writing an edge per child. An edge you passed explicitly always wins.
- validate (`boolean`) — Include a graph_validate report of what the write left behind, in the same response. Worth passing after a batch; off by default because it scans the whole graph.

## `graph_add_source_attachment` — write

Attaches a source-code location to a node or edge in one call: builds the VS Code deeplink from the path and line, stores the excerpt alongside it, and labels it. Use this instead of hand-building a data item, so every source attachment in the graph has the same shape and graph_filter's sourcePath can find it.

- on (`"node" \| "edge"`) — Whether the target is a node or an edge. Defaults to "node".
- **id** (`string`) — Id of the node or edge to attach to.
- **path** (`string`) — File path. Absolute, or relative with repoRoot given — a deeplink only opens if the path resolves on the reader's machine.
- line (`integer`) — Line to open at. Strongly recommended: without it the link drops the reader at the top of the file.
- endLine (`integer`) — Last line of the region, for the label.
- column (`integer`) — Column to open at.
- excerpt (`string`) — The source text itself, stored with the link so the graph is readable without the repository checked out.
- label (`string`) — Display name. Defaults to "path:line".
- repoRoot (`string`) — Absolute path a relative "path" is joined onto.
- dataId (`string`) — Optional stable attachment id, unique within this node/edge.
- uri (`string`) — Overrides the generated deeplink entirely — for a non-VS-Code target.

## `graph_validate` — read

Reports quality problems rather than structural ones: edges pointing at missing nodes, nodes with no edges, missing descriptions, empty or line-less source attachments, duplicate attachment ids, and directed cycles. Every issue carries a severity — only "error" means something is certainly wrong; an orphan node or a cycle is legal and sometimes intended. Worth running after any batch write. Read-only: it never changes or rejects anything.

No arguments.

## `data_add` — write

Attaches any data item to a node or edge: text, an image, a file, or a link. kind is an open string ("text", "image", "file", "link", "insight" are what the UI renders specially).

- **on** (`"node" \| "edge"`) — Whether the attachment hangs off a node or an edge.
- **targetId** (`string`) — Id of that node or edge.
- dataId (`string`) — Optional stable id, unique within this node/edge. Generated when omitted.
- **kind** (`string`) — What this is, e.g. "text", "image", "file", "link".
- name (`string`) — Display name.
- mimeType (`string`) — MIME type, e.g. "image/png".
- **source** (`object`) — Where the content lives. Exactly one of the three shapes.

## `data_update` — write

Changes the fields you pass on one attached data item. The merged result is re-validated, so a source you narrow to an unusable shape is rejected rather than stored.

- **on** (`"node" \| "edge"`) — Whether the attachment hangs off a node or an edge.
- **targetId** (`string`) — Id of that node or edge.
- **dataId** (`string`) — Id of the data item to change.
- kind (`string`) — New kind.
- name (`string`) — New display name.
- mimeType (`string`) — New MIME type.
- source (`object`) — Where the content lives. Exactly one of the three shapes.

## `data_remove` — write

Detaches one data item — including an insight — from its node or edge. Not undoable.

- **on** (`"node" \| "edge"`) — Whether the attachment hangs off a node or an edge.
- **targetId** (`string`) — Id of that node or edge.
- **dataId** (`string`) — Id of the data item to remove.

## Nested shapes

```jsonc
// graph_apply_patch changes[] — applied in order, all-or-nothing
{ "op": "createNode", "id": "orders-db", "node": { "type": "database", "name": "Orders DB", "properties": { "description": "…" } } }
{ "op": "createEdge", "id": "e-api-reads-orders", "edge": { "source": "checkout-api", "target": "orders-db", "type": "reads" } }
{ "op": "updateNode", "id": "checkout-api", "node": { "properties": { "owner": "payments-team" } } }
{ "op": "deleteEdge", "id": "e-old" }

// data_add source — exactly one shape
{ "type": "inline", "text": "Retries 3x with jitter" }            // kind "text" / "insight"
{ "type": "inline", "base64": "…" }                               // ≤ 2 MB decoded; prefer file_upload
{ "type": "uri", "uri": "https://… | vscode://file/abs/path:42" } // kind "link", "image", "file"
{ "type": "object", "provider": "minio", "bucket": "…", "key": "…" } // from file_upload

// journey (journey_set / graph_set_info.journey)
{ "title": "…", "description": "…", "steps": [ { "id": "overview", "title": "…", "narration": "…", "nodeIds": [] } ] }
```

Result envelope for every tool: `{ "status": "success", "data": … }` or
`{ "status": "validation_error" | "conflict" | "not_found" | "failure", "message": "…", "details": … }`.
